# M5 性能报告

日期：2026-11-04 ｜ 版本：v0.7.0 ｜ 机器：Windows基准设备（测量时存在后台负载，绝对值偏悲观，相对结论可靠）

## 1. 测量方法

**模拟侧（Node 环境，无渲染干扰）**：`BENCH=1 npx vitest run src/bench/sim-bench.test.ts`

- 预热 60 步（冷启动首步比热态慢一个数量级，JIT 效应，必须预热）
- 1920×1080 世界，计时 120 步取均值（大粒子数档减半，极端密集档 30 步）

**渲染侧（真实浏览器）**：预览地址加 `?bench=1`

- 每档预热 60 帧 + 计时 180 帧，rAF 真实节奏，分别记录模拟/渲染 CPU 耗时与 FPS
- 结果页显示并自动下载 JSON（`emergent-light-bench-*.json`）

## 2. 模拟侧数据（热态，ms/步）

| 粒子数 | Particle Life | Boids |
|---|---|---|
| 500 | 1.7 | 2.4 |
| 1000 | 5.5 | 4.5 |
| 2000 | 18.9 | 23.6 |

极端密集（空间哈希单格过热压力）：1000 粒子 @400×300 ≈ 80–100 ms/步。

## 3. 发现

1. **Particle Life 扩展性 ≈ O(n²)**：作用半径固定，粒子数翻倍 ⇒ 密度翻倍 ⇒ 每个粒子的邻居数翻倍 ⇒ 总相互作用 ×4。2000 粒子时单步 ~19 ms，已超过 60 fps 帧预算（16.7 ms）。**实用上限约 1000–1500 粒子**（当前默认 500，余量充足）。
2. **Boids 同样超线性但系数更小**（感知半径 90px 远小于 PL 的作用半径）：2000 粒子 23.6 ms/步，实用上限约 1000–1200。默认 300，余量充足。
3. **极端密集是设计内接受的退化**：不截断真实相互作用（设计文档 §8 的既定决策），密集场景下单格过热、单步耗时两个数量级上升。当前默认参数与世界尺寸不会进入该 regime；控制面板把数量上限钳在 500（PL）/300（Boids），高数量配置 + 把粒子聚成一点才触发。
4. **冷启动首步 ~15–95 ms**（JIT + 矩阵/存储初始化），预热 60 步后稳定。浏览器常规运行无感（首帧在面板显示前）。
5. 测量时机负载敏感：完整基准在机器繁忙时跑出过 10 倍膨胀的数值，所有决策应以安静环境复测为准（上表为安静环境数值）。

## 4. 瓶颈归属（待浏览器基准补全）

模拟侧已量化：默认规模（PL 500 / Boids 300）单步 1.7 / 2.4 ms，占帧预算 ~12%。

渲染侧（Canvas 2D，1/4 分辨率光晕层 + DPR ≤ 1.5）需要 `?bench=1` 的真实数据：
- 若渲染 CPU 耗时 < 8 ms 且 FPS ≥ 55 @1920×1080 → Canvas 2D 达标，**不引入 WebGL**（见 adr-001）。
- 若不达标 → 启动 WebGL 2 后端实现（Renderer 接口已预留，模拟零改动）。

## 5. 浏览器基准结果（实机，2026-11-04 22:17）

环境：1280×679 @ DPR 2（渲染器封顶 1.5），Edge 156，原始数据 `docs/bench-20261104.json`。

| 规模 | FPS | 模拟 ms/帧 | 渲染 ms/帧 | 瓶颈 |
|---|---|---|---|---|
| PL 500（默认） | **59.7** | 8.0 | 3.1 | 接近预算上限但达标 |
| PL 1000 | 35.0 | 23.6 | 4.6 | 模拟 |
| PL 2000 | 10.0 | 89.1 | 10.3 | 模拟 |
| Boids 300（默认） | **60.0** | 2.5 | 2.9 | 无 |
| Boids 600 | 60.0 | 2.6 | 3.1 | 无 |
| Boids 1200 | 60.0 | 2.5 | 3.0 | 无 |

**结论：瓶颈在模拟，不在渲染。** 渲染管线全程 3–10 ms，默认规模 3 ms 远低于 8 ms 触发线；ADR-001 的 Canvas 2D 决策**确认成立，关闭 WebGL 2 议题**（除非未来要 2000+ 粒子）。

两个值得记录的观察：

1. **浏览器内模拟比 Node 慢约 4–5 倍**（PL 500：8.0 vs 1.7 ms）：主因是基准世界为 1280×679，密度是 Node 基准（1920×1080）的 2.4 倍——**屏幕越小、世界越挤，同一粒子数的开销越大**。控制面板的数量上限（PL 500 / Boids 300）在项目机器上恰好留住了 60 FPS；若未来在更小窗口使用，可把数量降到 300–400。
2. **Boids 在 1200 粒子内全程满帧**：感知半径小 + 空间哈希，扩展性优秀，数量上限有充足上调空间（按性能需求评估）。
