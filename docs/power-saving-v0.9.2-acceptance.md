# v0.9.2 自动后台节能


## 2026-11-05：v0.9.2 自动后台节能（待实机验收）

阶段需求为完成此前未实现的后台节能。本版系统组新增默认开启且保存选择的“自动后台节能”和运行状态。正常可见维持动画循环；部分遮挡目标约 30 FPS（模拟仍以固定步长补进，主要减少绘制）；主屏桌面工作区确认被不透明窗口完全覆盖时取消动画及绘制定时器，不推进模拟，只保留约 750ms 状态检查。读取失败保持运行。透明、带自定义区域或无法确认遮挡的窗口保守处理，不盲目休眠。系统任务栏不计入覆盖工作区。

Windows 原生端：过滤最小化、隐藏、cloaked、桌面/任务栏窗口；用矩形减法累计覆盖，普通圆角窗口仅采纳向内缩进区域；DWM 窗口边界和显示器边界统一到线程级 per-monitor DPI 物理坐标，完成后恢复原线程 DPI。通过输入桌面探测安全/锁屏桌面，通过 Windows 电源通知监听显示关闭与系统挂起/恢复；通知句柄随窗口销毁注销。

调度与手动暂停分开，不调用 engine.resume 来自动唤醒。休眠不积累模拟时间、彩蛋事件或颜色淡出。唤醒首帧不补算后台间隔；异常长帧也丢弃时间。手动暂停额外停止绘制，仅低频检查恢复状态。呼吸使用活动秒累计，拖尾和亮度低通按活动帧时长换算，核心与光晕沉积做时间补偿；低帧率模拟仍保留固定 1/60 步长。休眠时停止查询光标。

验证：TypeScript/Vite 构建、Windows x64 release 和 NSIS 打包通过；前端完整测试 106 通过、1 跳过（低并发重跑），原生覆盖区域测试 2 通过。实际调度测试确认休眠 60 秒期间模拟/绘制调用不增加、唤醒不补算且保留手动暂停；其他测试覆盖活动时钟、异常时间间隔、节能关闭和 30/60/120Hz 衰减等价。首次完整测试与 Rust 编译并行，旧 Boids 长跑测试触发 5 秒超时；等待编译后以 maxWorkers=2 全套重跑通过，未放宽断言或测试超时。

实机验收：1. 开启节能，用普通窗口遮住部分桌面，性能信息降至约 30 FPS；2. 最大化不透明应用覆盖桌面，等待约 1 秒，任务管理器观察资源占用；3. 回到桌面，粒子不重置、不跳进、不集中触发彩蛋；4. 手动暂停后遮挡再恢复仍暂停；5. 锁屏/系统熄屏恢复；6. 关闭自动节能后覆盖不再触发本应用的自动休眠。浏览器隐藏标签页也会暂停。

实际 CPU/GPU 占用百分比、系统锁屏/熄屏通知和桌面遮挡识别率尚未实测，不预先承诺节省比例。复杂透明或自定义窗口可能只降帧而不休眠；多屏、显示器热插拔及 Explorer 宿主恢复仍是旧限制。后台 OS/WebView 定时器节流可能使唤醒检测慢于 750ms。下一步按实际观感和占用数据验证。
